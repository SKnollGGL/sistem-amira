01

What this is

Amira Consulting replaces the first, most repetitive layer of a bureaucracy consultancy — intake, document collection, form-filling, status updates — with a conversational AI assistant a client can reach on the channel they already use.

I designed the product and the entire technical system: the conversation architecture, the data model, the compliance posture, the multi-language site, and the deployment and monitoring tooling around it. I built it using an AI-augmented engineering workflow — directing an AI coding agent through architecture decisions, implementation, testing, and live production incident response — the same way a technical lead directs a team, but compressed into a single fast iteration loop. Every design call, every test, every rollback decision in the stories below was mine to make and defend.

02

System architecture

One conversation engine, shared across every entry point, so a client gets the same reasoning and the same case history whether they write on WhatsApp, Telegram, or come in through an outbound sales call.

03

What I built

Conversation engine

Multi-turn dossier collection

A single n8n workflow drives structured data collection across 14 service packages, using Claude to extract dossier fields from free-form chat and track per-client state in Postgres.

Documents

Generation & e-signature pipeline

A Python/FastAPI service generates client-specific PDFs on demand and produces signature links for documents that legally need a client's consent before submission.

Multi-channel

WhatsApp, Telegram, voice, SMS

WhatsApp and Telegram both reuse the same conversation "brain." A separate outbound sales-call system pairs Twilio Voice with AI-generated speech and live Claude-driven dialogue.

Data architecture

Channel-agnostic identity model

A client-ID and case-number scheme that never uses phone number as a system key, and preserves full history through alias resolution whenever an identifier changes.

Compliance

Built-in regulatory posture

EU AI Act Article 50 disclosure in every conversation; GDPR-conscious digital power-of-attorney consent before anything is submitted to a German institution.

Product & growth

Multilingual site, referral engine

An 8-language site with browser-language auto-detection, plus affiliate/referral commission tracking and automated lead follow-up.

Engineering highlights

A production system with real clients breaks in real ways. These are incidents I actually diagnosed and resolved — the kind of story that holds up under a follow-up question.

Incident response & rollback discipline

While migrating dozens of nodes off inline plaintext API keys onto managed credentials, I hit an undocumented platform limitation causing silent failures in invoicing, commissions, and consent confirmations. I built a debug-capture technique to surface the real error, fully reverted to a known-good state within the same session, verified the fix against a real client conversation, and wrote a risk-tiered migration plan for a safer future attempt.

Systematic production debugging

Swept execution error logs across every active workflow and found a renewal-reminder feature that had been failing identically, every day, for five straight days — a missing expression prefix was sending a date filter to the database as a literal string. Fixed and confirmed against the next scheduled run.

Root-causing infrastructure fragility

Traced a recurring "something's broken overnight" pattern to a PDF-generation server depending on a personal machine staying powered on, by correlating process start times with outage windows, and scoped a proper fix instead of patching the symptom.
